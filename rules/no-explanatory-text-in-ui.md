# 결과물에 부속 설명 금지

개발 결과물 자체에 부속 설명을 달지 않는다. 예: "리치-텐파이를 잡았습니다" 같은 상태 해설 문구. 내부 로직을 결과물에 서술하는 것도 같은 이유로 금지. UI는 단어 위주로 직관적으로 만든다.

단, 도움말·설명 목적의 영역에서는 문장을 쓸 수 있다. 그러나 절대로 주저리처럼 보이게 쓰지 않는다. 이런 문장은 작성 전 사용자에게 전문을 제시하고 완전히 검토받는다.

**Why:** 과도한 정보 부하를 일으킨다. 화면은 필요한 것만 보여주고 나머지는 직관으로 파악하게 둔다. 도움말은 문장이 필요한 자리지만, 길어지는 순간 같은 정보 부하가 된다.

**How to apply:** 라벨/버튼/상태는 문장이 아니라 단어나 짧은 구로 표기한다. 계산 과정, 판정 근거, 알고리즘 설명을 화면이나 로그 출력에 노출하지 않는다. 툴팁·헬프 텍스트·안내 문단도 요청받지 않았다면 추가하지 않는다. 도움말·설명 영역의 문장은 짧게 끊고 군더더기를 뺀 뒤, 확정 전에 사용자 검토를 받는다. [no-comments-clean-code](no-comments-clean-code.md)와 같은 방향의 원칙.
