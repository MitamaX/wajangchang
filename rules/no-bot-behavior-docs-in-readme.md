# README에 봇 규칙 설명 금지

README에는 엔진 규격만 적는다. 봇이 지금 어떤 규칙을 쓰는지, 그 규칙이 어떤 상황에 무엇을 내는지는 적지 않는다.

- 적는다: 스타일·규칙 JSON 스키마, `when`/`while`/`steps` 항목표, 조건 이름과 판정 의미, 실행 순서·중단 규칙, CLI 옵션과 경로.
- 적지 않는다: 개별 행동 파일의 동작 설명, 규칙 목록의 적용 순서, 특정 기술 연결의 프레임 수치, 어떤 스타일이 어떤 규칙을 담고 있는지.

**Why:** 봇의 규칙은 언제든 바뀐다. 규칙을 고칠 때마다 README를 같이 고쳐야 하고, 빠뜨리면 문서가 코드와 어긋난 채 남는다. 실제로 `recovery-2p` 설명이 코드·테스트와 반대로 적혀 있었다. 규칙의 내용은 규칙 JSON 자체가 이미 갖고 있으므로 문서에 옮겨 적는 것은 중복이다.

**How to apply:** 새 행동을 추가해도 README를 건드리지 않는다. 엔진에 새 조건·새 실행 방식을 더했을 때만 항목표에 한 줄 추가한다. 조건의 의미는 그 조건을 쓰는 규칙 이름이나 기술 이름 없이 일반형으로 쓴다. [dry-code-efficiency-discipline](dry-code-efficiency-discipline.md), [no-explanatory-text-in-ui](no-explanatory-text-in-ui.md)와 같은 방향 — 중복 설명은 결함이다.
